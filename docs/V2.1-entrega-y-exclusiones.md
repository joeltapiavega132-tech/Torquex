# Torquex V2.1: preparación de entrega

## Dos publicaciones

- **Demo:** el sitio actual de Netlify sigue tomando `main` y la edición `demo`. Sus registros se guardan en el navegador de quien hace la prueba.
- **Entrega vacía:** la rama `v2.1` prepara la edición `client`, seleccionada con `VITE_APP_EDITION=client`. Esta edición bloquea las operaciones hasta terminar la autenticación y la persistencia compartida. Su base de datos empieza sin productos, ventas ni gastos de ejemplo. Cada cliente dedicado debe tener su propio proyecto Supabase y sitio Netlify.

El paquete V2.1 está en desarrollo. La comprobación del endpoint Auth de Supabase fue satisfactoria, pero el proyecto todavía no tiene las tablas de las migraciones. Por ello, V2.1 no se debe presentar como una instalación operativa.

## Qué queda fuera de GitHub

| Archivo o carpeta | Motivo |
| --- | --- |
| `.env`, `.env.*` salvo `.env.example` | Contienen configuración local y posibles credenciales. |
| `node_modules/`, `dist/`, `coverage/`, `*.tsbuildinfo` | Se generan al instalar, compilar o comprobar código. |
| `.netlify/`, `.vercel/`, `supabase/.temp/`, `supabase/.branches/`, `.supabase/` | Estado local de herramientas y enlaces a servicios. |
| `*.log`, `*.json.bak`, `*.sql.bak`, `*.dump`, `*.backup`, `*.sqlite`, `*.sqlite3`, `*.db`, `*respaldo*.json` | Registros y respaldos, incluidos posibles datos de clientes. |
| `*.pem`, `*.p12`, `*.pfx`, `*.key` | Llaves y certificados privados. |

Estos patrones están en `.gitignore`. Antes de cada publicación conviene comprobar `git status` y `git ls-files` para detectar algún archivo sensible añadido antes de establecer las exclusiones. Los scripts SQL de `supabase/migrations` sí son código fuente y deben versionarse.

## Qué se configura en Netlify

- Build: `npm run build`; publicación: `dist`.
- Demo: `VITE_APP_EDITION=demo` o variable ausente; sin claves Supabase.
- Entrega: `VITE_APP_EDITION=client`, `VITE_SUPABASE_URL` y `VITE_SUPABASE_ANON_KEY` como variables del sitio específico.
- La clave `anon` es pública por diseño y requiere políticas RLS correctas. `SUPABASE_SERVICE_ROLE_KEY`, contraseñas de base de datos y tokens personales se guardan solo en el entorno del servidor Supabase. Nunca se configuran con prefijo `VITE_`, en Netlify ni en GitHub.
- Las funciones Edge necesitan `APP_ORIGIN` con el origen exacto del sitio de entrega.

## Pendiente para habilitar V2.1

1. Aplicar y revisar las migraciones en el proyecto Torquex vacío.
2. Crear la primera cuenta administradora con el correo correcto, cerrar el registro público y desplegar las funciones de invitación.
3. Implementar interfaz de acceso, aceptación de invitación, administración de usuarios y recuperación de cuenta.
4. Reemplazar el guardado local por operaciones transaccionales con permisos y auditoría de servidor para inventario, ventas, cobros, devoluciones, importaciones y gastos.
5. Mostrar los nombres de las personas responsables en las fichas y reportes.
6. Verificar varios usuarios simultáneos, stock, saldos, respaldos y seguridad antes de activar la entrega.

SRI permanece visible y bloqueado; no se emiten comprobantes.
