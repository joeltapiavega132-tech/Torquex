## Antes de publicar y usar registros del negocio

1. Publicar la rama `v2.2` en GitHub y crear un sitio Netlify separado que construya con `npm run build` y publique `dist`. Configurar `VITE_SUPABASE_URL` y `VITE_SUPABASE_ANON_KEY` en el sitio; no incluir `.env` ni claves de servicio.
2. Cambiar `auth.site_url`, las redirecciones permitidas y el secreto `APP_ORIGIN` de `http://localhost:5173` al origen HTTPS final. Comprobar inicio de sesión, recuperación de contraseña e invitaciones desde ese dominio.
3. Probar con al menos dos cuentas autorizadas: permisos por rol, invitación usada o vencida, venta simultánea de la última unidad, cobro, devolución, reembolso, anulación, corrección de entrada y gasto, nombres responsables y reportes. Confirmar que ninguna operación sobrescribe otra.
4. Definir y probar el procedimiento de respaldo y restauración de la base compartida. La interfaz solo descarga un archivo JSON; no restaura el estado del equipo y no programa copias automáticas.
5. Verificar el envío de correos a personas fuera de la organización de Supabase y configurar SMTP propio si el servicio predeterminado no permite invitarlas.

## Prueba local

En la carpeta Torquex, ejecutar `npm ci` y `npm run dev -- --host localhost --port 5173 --strictPort`. La aplicación local utiliza el proyecto Supabase de Torquex, no una base aislada. Auth y `APP_ORIGIN` apuntan temporalmente a `http://localhost:5173`.
